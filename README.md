# フェアトレード・チャレンジ ～チョコレートの旅～

中高生向け・**4〜6人同時対戦型**のフェアトレード学習ゲーム（試作版 / MVP）。

生徒はそれぞれチョコレート会社の社長になり、5年間（5ラウンド）の経営を競います。
最後に **利益ランキング** と **サステナビリティ総合ランキング** の2つが発表され、
「利益で1位の会社が、総合でも1位とは限らない」という体験から話し合いにつなげます。

- ログイン不要・氏名登録不要・個人情報の収集なし・広告なし
- 学校の端末のブラウザ（Chrome / Edge / Safari）だけで動作。インストール不要
- **外部パッケージゼロ**。`npm install` は不要で、Node.js があれば動きます

---

## 1. 起動する

```bash
node server/index.js
```

これだけです。起動すると、アクセス先のURLが表示されます。

```
  🍫  フェアトレード・チャレンジ ～チョコレートの旅～
  ───────────────────────────────────────────────
  先生用   : http://localhost:3000/teacher
  生徒用   : http://localhost:3000/play

  同じWi-Fiの端末からは、こちらのURLで開けます:
    http://192.168.1.24:3000/play
```

ポートを変えたいときは `PORT=8080 node server/index.js`。

### ゲーム内のお金について

初期資金は **10,000,000円（1,000万円）**。ゲーム中の金額はすべて円です。

画面表示は読みやすさのため **万円** にそろえています（`1,000万円` `+517万円` など）。
円そのままで出したい場合は `config/rules.mvp.json` の1か所だけ変えてください。

```jsonc
"currency": { "label": "円", "unit": 1, "unitLabel": "円" }   // → 10,000,000円 と表示
"currency": { "label": "円", "unit": 10000, "unitLabel": "万円" } // → 1,000万円（既定）
```

内部では常に「円」で計算しており、表示単位を変えても計算結果は変わりません。

### トップページの背景イラストを差し替える

`public/img/` に **`hero.webp` / `hero.jpg` / `hero.png`** のいずれかの名前で画像を置くと、
トップページの背景として自動的に使われます。**再起動もコード変更も不要**です。

置かれていないときは、同梱のSVGの挿絵と配色で表示されます（画像が無くても壊れません）。
詳しくは [public/img/README.md](public/img/README.md) を参照してください。

---

**トップページ（`/`）が入口です。** ここから「ゲームに参加する（生徒）」と
「先生としてルームを作成」の両方へ進めます。生徒にはトップページのURLだけを伝えれば足ります。

```
                    ┌─────────────────┐
                    │   /  トップ      │  ゲームの流れ / 遊び方 / お知らせ
                    └───┬─────────┬───┘
              生徒      │         │      先生
                        ▼         ▼
                 /play  ◀────────▶  /teacher     ← 互いに行き来できます
```

> **必要なもの**: Node.js 20 以上（開発・動作確認は Node.js 24 で実施）

## 2. 授業での流れ

### 先生

1. `/teacher` を開いて **「ルームを作成する」** を押す
2. 画面に出る **6けたの番号とQRコード** を、プロジェクタや黒板で生徒に見せる
3. 全員が入ったら **「ゲームを開始する」**
4. あとは **「次へ ▶」** を押していくだけ

各ラウンドでは、その年の市場ニュース（イベント）と、誰が決定済みかが大きく表示されます。
決まらない生徒がいても **「締め切って結果を出す」** で先へ進められます。

### 生徒

1. QRコードを読む、または `/play` を開く
2. 6けたの番号と名前（ニックネーム可）を入れる
3. 毎年、5つのことを決める
   - カカオの仕入れ先（一般市場 / 直接取引 / 国際フェアトレード認証）
   - 砂糖の仕入れ先（同上・カカオとは別に選べます）
   - 販売価格（安い / 標準 / 高い）
   - 広告費（0 / 50 / 100）
   - 生産者・地域への追加還元（0 / 30 / 60）
4. 「この内容で決定する」を押す。**締め切りまでは何度でも選び直せます**

## 3. 1人で動作確認する（先生の予行演習・開発時）

先生用コンソールの **「🤖 練習用AIを追加」** を押すと、CPUプレイヤーが1人増えます。
4回押せば、**PC1台だけで4人対戦を最後まで確認**できます。

AIは3種類の考え方（利益重視 / バランス / フェアトレード重視）で、
ルールJSONの数値を読んで自分で計算して打ってきます。数値を変えれば強さも自動的に追従します。

## 4. 教室で起きることへの対策

学校のネットワークと端末で実際に起きることを、試作の段階から想定しています。

| 起きること | このアプリの動作 |
|---|---|
| 生徒がブラウザを更新した / 「戻る」を押した | 自動的に同じ会社に復帰します（選びかけの内容も残ります） |
| Wi-Fiが一瞬切れた / 端末がスリープした | 自動で再接続します。画面右上に接続状態が出ます |
| タブを閉じてしまった | 参加画面に「前回の続きから戻る」ボタンが出ます |
| 生徒が決めないまま時間になった | 先生が締め切ると、その時点の選択（未選択なら既定値）で計算されます |
| 生徒が途中で離脱した | 残ったメンバーで続行できます。AIで人数を埋めることもできます |
| 先生が誤ってページを閉じた | 「前回のルームに戻る」で復帰できます |
| サーバが再起動した | ルームの状態はディスクに保存されており、復元されます |
| 定員を超えて参加しようとした | 人数の上限で断ります |
| ブラウザから不正な値を送られた | サーバ側で必ず検証します（後述） |

### 不正・食い違いへの対策

**計算は必ずサーバで行い、ブラウザからは「どれを選んだか」しか受け取りません。**
金額・点数・順位をブラウザから送ることはできず、送っても無視されます。
存在しない選択肢を送れば既定値に落とします。
そのため、端末ごとに結果が食い違うことがありません。

## 5. 数値・文章を変える

**ゲームのルール（数値・選択肢・イベント・説明文）はすべて `config/*.json` にあります。**
プログラムの変更は不要です。

| ファイル | 内容 |
|---|---|
| `config/rules.mvp.json` | 既定のルール（中学・高校版）。**通常はここだけ編集します** |
| `config/rules.elementary.json` | 小学校版（3ラウンド・決めることを減らした版） |
| `config/rules.spec.json` | 発注仕様の数値そのまま（比較検証用） |
| `config/companies.json` | 生徒に割り当てる会社名と色 |

ルールセットは、先生用コンソールのルーム作成画面で選べます。

```jsonc
// 例: フェアトレード認証カカオの価格を変える
{ "id": "fairtrade", "name": "国際フェアトレード認証カカオ", "unitCost": 140, ... }
```

`rules.elementary.json` のように `"extends": "rules.mvp.json"` と書けば、
**変えたい数値だけ**を書いた新しいルールセットを追加できます。

編集後は、壊れていないかを確認できます。

```bash
npm test                  # ルールの検証 + ゲームが最後まで成立するかの通しテスト
node tools/simulate.js    # 2,000ゲーム対戦させ、支配的な戦略がないかを確認
node tools/tune.js        # バランスの良い数値の組み合わせを自動で探す
```

書式に誤りがあるときは**サーバが起動せず、理由を表示します**（授業中に気づく事態を防ぐため）。

> 📄 **数値の根拠と、発注仕様からの変更点は [docs/BALANCE.md](docs/BALANCE.md) にまとめています。**

## 6. 公開する（学校から使えるようにする）

### A. 教室のPC1台をサーバにする（最も手軽・推奨）

先生のPCで `node server/index.js` を実行し、表示された
`http://192.168.x.x:3000/play` を生徒に開いてもらいます。
インターネットに出ないので、学校のフィルタリングの影響を受けにくい方法です。

- 同じWi-Fi（同じセグメント）に全端末がいること
- Windows のファイアウォールで、初回に「アクセスを許可」を選ぶこと

### B. クラウドに置く（複数校・自宅からも使う場合）

`PORT` 環境変数を読むだけの構成なので、Node.js が動く PaaS ならそのまま動きます。

```
起動コマンド : node server/index.js
Node バージョン: 20 以上
ビルド      : 不要（依存パッケージなし）
```

**WebSocket に対応したサービスを選んでください**（Render / Railway / Fly.io / VPS など。
WebSocket を通さないサーバレス環境では動きません）。

HTTPS のサイトでは、クライアントは自動的に `wss://` で接続します。設定は不要です。

> ルームの状態は `data/rooms.json` に保存されます。ファイルを保持できない環境でも
> 動作しますが、再起動時に進行中のゲームは復元されません。
> `NO_PERSIST=1` で保存を無効にできます。

## 7. 構成

```
config/           ルール（数値・文章）… ここを変えればゲームが変わる
  rules.mvp.json          既定ルール
  rules.elementary.json   小学校版（extends で差分のみ）
  rules.spec.json         発注仕様どおり（比較用）
  companies.json          会社名・色
  news.json               トップページの「お知らせ」（ここを直せば表示が変わります）

shared/           サーバとブラウザの両方から使う共通コード
  engine.js               ゲームの計算（純粋関数のみ。通信もDOMも知らない）
  rng.js                  シード固定の乱数

server/
  index.js                HTTP + WebSocket の入口
  ws.js                   WebSocket の自前実装（RFC 6455）
  room.js                 1ゲーム分の状態管理・進行
  store.js                ルームの保管と保存・復元
  rules.js                ルールJSONの読み込み・継承・検証
  bots.js                 練習用AI

public/           ブラウザ側
  index.html              トップページ（生徒用・先生用の入口をつなぐハブ。挿絵はインラインSVG）
  play.html               生徒用
  teacher.html            先生用コンソール
  css/  home.css（トップ） app.css（ゲーム画面）
  js/   home.js  net.js（再接続つき通信） ui.js components.js teacher.js play.js qr.js

test/             npm test で全部走ります
tools/            simulate.js（バランス検証） tune.js（自動調整）
docs/             BALANCE.md（数値の根拠） TEACHER-GUIDE.md（授業案）
```

### 設計の考えかた

1. **ルールとプログラムを分ける** — 数値・文章はすべて JSON。教材の改訂でコードを触らない
2. **計算はサーバに集約** — 結果の食い違いと不正を構造的に防ぐ
3. **画面は状態を描くだけ** — 再接続・端末の入れ替えで表示がズレない
4. **乱数はシード固定** — 同じ入力なら必ず同じ結果。再起動しても進行が変わらない
5. **依存パッケージゼロ** — 学校のネットワークで `npm install` が通らなくても動く

## 8. テスト

```bash
npm test
```

124個のテストが走ります（Node.js 標準のテストランナーのみ使用。外部ツール不要）。

| ファイル | 確認していること |
|---|---|
| `test/engine.test.js` | 計算式、イベントの効果、順位付け、不正入力の扱い、決定性 |
| `test/e2e.test.js` | **本物のサーバに4人が接続して5ラウンド対戦**、再接続、締め切り、権限、不正送信 |
| `test/client-home.test.js` | トップページから生徒用・先生用の両方へ行けるか、遊び方とお知らせの表示 |
| `test/client-play.test.js` | **生徒用画面（play.js）を本物のサーバ相手に最初から最後まで操作**。参加→5ラウンド→結果、通信断からの自動復帰 |
| `test/client-teacher.test.js` | **先生用コンソール（teacher.js）を実際にクリック操作**。ルーム作成→AI追加→開始→締め切り→3段階の結果発表→CSV出力 |
| `test/protocol.test.js` | WebSocketのハンドシェイクとフレーム処理、レート制限、ルール検証 |
| `test/render.test.js` | 画面部品が、実際のゲーム結果から正しく組み立てられるか |
| `test/qr.test.js` | QRコードが規格どおりか（形式情報・型番情報を規格値と照合） |

`test/dom-stub.js` に小さなDOM実装を用意し、**ブラウザを起動せずに実際の画面スクリプトを
そのまま実行**しています（HTMLも本物を読み込みます）。見た目の確認まではできませんが、
「生徒や先生が触ったときに動くか」はここで確認できます。

## 9. この試作版に含まれていないもの

発注時の「MVPでは簡略化する部分」に沿って、以下は実装していません。

- プレイヤー間の直接取引・交渉機能（初期の構想にあった「共同仕入れ」など）
- 高度なアニメーションや本格的なグラフィックデザイン
- 管理画面からのルール編集UI（現状はJSONファイルの編集）
- 実在するフェアトレード認証生産者データとの連携
- 農家・輸入会社・メーカー・小売など、役割を分けるサプライチェーン版

いずれも、ゲームロジックとデータを分離した現在の構成の上に追加できます。
